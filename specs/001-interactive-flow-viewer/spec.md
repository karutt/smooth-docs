# Feature Specification: Interactive Flow Viewer and Editor

**Feature Branch**: `001-interactive-flow-viewer`

**Created**: 2026-08-26

**Status**: Draft

**Input**: User description: "Markdownまたは外部の構造化テキストから、Mermaidよりリッチな
ワークフロー図を素早く表示したい。図は閲覧できるだけでなく、ローカル執筆環境で視覚的に
編集し、元のテキストへ安全に保存できる必要がある。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ワークフローを視覚的に編集して保存する (Priority: P1)

ドキュメント執筆者は、Markdown内または外部ファイルに記述されたワークフローを図として
開き、ノード、接続、レーン、配置、説明を視覚的に変更し、その変更を元の定義へ保存する。
保存後も定義は人が読める状態を保ち、ページを再読み込みしても編集結果が再現される。

**Why this priority**: 視覚的な編集とテキストへの往復保存が、静的な図生成機能との差別化で
あり、この機能の中核価値だからである。

**Independent Test**: 4ノードの有効な定義を用意し、ノード移動、ノード追加、接続変更、
プロパティ変更を視覚的に行って保存する。対象の定義だけが更新され、再読み込み後に同じ図が
表示されれば、このストーリー単体で価値を検証できる。

**Acceptance Scenarios**:

1. **Given** ローカル執筆環境で有効なワークフローが表示されている、**When** 執筆者が
   編集モードを開いてノードを移動し保存する、**Then** 新しい配置が元の定義へ反映され、
   再読み込み後も維持される。
2. **Given** 編集モードが開いている、**When** 執筆者がノードを追加し、既存ノードとの接続と
   ラベルを設定して保存する、**Then** 図と元の定義の両方に追加内容が反映される。
3. **Given** 未保存の変更がある、**When** 執筆者が破棄を選択する、**Then** 元の定義は変更
   されず、図は最後に保存された状態へ戻る。
4. **Given** 編集開始後に対象ファイルが別の操作で変更された、**When** 執筆者が保存する、
   **Then** 上書きは行われず、競合を解消するための案内が表示される。
5. **Given** 公開用の静的サイトを閲覧している、**When** 読者が同じ図を開く、**Then** 図は
   閲覧できるが、編集またはローカルファイル保存の操作は表示されない。

---

### User Story 2 - 複雑なワークフローを探索して理解する (Priority: P2)

読者は、大きなワークフローを拡大、縮小、移動、検索し、選択したノードの詳細や関連経路を
確認する。読者は図全体を追わなくても、注目する処理の上流、下流、例外経路を理解できる。

**Why this priority**: 閲覧者が複雑な図から必要な情報を短時間で得られなければ、リッチな
表現を追加してもドキュメントとしての価値が低いためである。

**Independent Test**: 20ノード以上のワークフローで、検索、全体表示、ノード詳細、上流・
下流フォーカスを順に操作し、対象の情報だけを確認できれば独立して検証できる。

**Acceptance Scenarios**:

1. **Given** 表示領域より大きい図がある、**When** 読者が拡大、縮小、移動、全体表示を行う、
   **Then** 図の任意の領域と全体像を切り替えて確認できる。
2. **Given** 多数のノードがある、**When** 読者がノード名または説明の一部を検索する、
   **Then** 一致するノードが示され、選択するとその位置へ移動する。
3. **Given** ノードが選択されている、**When** 読者が詳細または関連経路を開く、**Then**
   説明、属性、関連リンク、上流、下流が確認できる。
4. **Given** 読者がキーボードのみを使用している、**When** 図へフォーカスしてノード間を
   移動する、**Then** 選択、詳細表示、全体表示を完了できる。

---

### User Story 3 - 定義を再利用し安全に保守する (Priority: P2)

執筆者は、大きなワークフローを外部の定義ファイルとして管理し、複数ページから参照する。
各ページは同じ定義の異なる初期表示や注目経路を示せる。定義変更はローカルプレビューへ反映
され、壊れた定義は既存ページの内容を黙って消さない。

**Why this priority**: 大きな図の重複を避け、複数のドキュメント間で一貫したワークフローを
保守できることが、共有ドキュメント基盤として重要だからである。

**Independent Test**: 1つの外部定義を2ページから異なる初期表示で参照し、視覚編集した変更が
両ページへ反映され、Markdown本文の他の部分が変化しないことを確認する。

**Acceptance Scenarios**:

1. **Given** 2ページが同じ外部定義を参照している、**When** 執筆者が一方のページから図を
   編集して保存する、**Then** 両ページが更新された同一の内容を表示する。
2. **Given** Markdown内に定義が埋め込まれている、**When** 執筆者が図を編集して保存する、
   **Then** 対象ブロックだけが更新され、前後のMarkdownは文字単位で保持される。
3. **Given** 外部定義の参照先が存在しない、または許可されたドキュメント領域外を指す、
   **When** ページを表示または保存する、**Then** 操作は安全に拒否され、対象箇所を特定できる
   メッセージが表示される。

---

### User Story 4 - 注目経路を再生し図を共有する (Priority: P3)

執筆者は、正常系、異常系、リトライなどの名前付き経路を定義・編集する。読者はその経路を
段階的に再生し、必要に応じて現在の図を共有可能な画像として取得する。

**Why this priority**: 基本的な編集と探索が成立した後に、説明、レビュー、プレゼンテーションで
図を活用しやすくする付加価値だからである。

**Independent Test**: 正常系と異常系の2経路を持つ図で、経路選択、ステップ再生、画像取得を
行い、定義された順序と表示内容が一致すれば独立して検証できる。

**Acceptance Scenarios**:

1. **Given** 複数の名前付き経路がある、**When** 読者が1つを選択して再生する、**Then**
   定義された順序で対象ノードと接続が強調される。
2. **Given** 執筆者が編集モードを開いている、**When** 名前付き経路の追加、並べ替え、削除を
   行って保存する、**Then** 変更が元の定義へ反映される。
3. **Given** 図が現在のテーマで表示されている、**When** 読者が画像として取得する、**Then**
   一時的な選択状態を含まない図全体が、読み取れる品質で取得される。

### Edge Cases

- ノードIDが重複している、または接続先のノードが存在しない場合。
- 循環、自己接続、分断されたノード、複数の開始・終了ノードを含む場合。
- ノードやレーンのラベルが極端に長い、空、または多言語を含む場合。
- 100ノード、150接続までの大きな定義を表示・編集する場合。
- 外部定義が見つからない、読み取れない、または許可領域外を参照する場合。
- 定義が途中までしか書かれていない状態でローカルプレビューが更新される場合。
- 編集中に元ファイルが別プロセスによって変更された場合。
- ノード削除によって接続、レーン、名前付き経路から参照されなくなる情報がある場合。
- 自動配置後に手動配置へ戻したい、または未保存の配置を破棄したい場合。
- 公開サイト上のソース参照がローカル絶対パスしか持たない場合。
- 対話機能が利用できない、画面幅が小さい、または支援技術を使用する場合。
- テーマ切り替え後に文字や接続のコントラストが不足する場合。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 執筆者は、Markdown内の構造化されたワークフロー定義を、その挿入位置で図として
  表示できなければならない。
- **FR-002**: 執筆者は、許可されたドキュメント領域内の外部定義をMarkdownから参照し、
  同じ図を複数ページで再利用できなければならない。
- **FR-003**: 各定義は、互換性を判断できる形式バージョンと、図を識別する安定した識別情報を
  持たなければならない。
- **FR-004**: ワークフローは、タイトル、説明、表示方向、レーン、ノード、接続、名前付き経路を
  表現できなければならない。
- **FR-005**: ノードは安定したID、種類、ラベルを必須とし、説明、所属レーン、担当、状態、
  リスク、関連リンクを任意で持てなければならない。
- **FR-006**: 初期リリースは、少なくともアクション、判断、サービス、外部システム、注記の
  5種類のノードを区別して表示・編集できなければならない。
- **FR-007**: 接続は始点と終点を必須とし、ラベルおよび通常、エラー、非同期の意味を任意で
  表現できなければならない。
- **FR-008**: レーンは安定したIDとラベルを持ち、ノードを担当領域ごとにグループ化できなければ
  ならない。
- **FR-009**: 有効な定義は自動的に読みやすく配置され、同じ入力と設定からは同等の配置が
  再現されなければならない。
- **FR-010**: 執筆者はローカル執筆環境で図を編集モードへ切り替えられなければならない。
- **FR-011**: 編集モードでは、ノードの追加、複製、削除、移動、および全プロパティの変更が
  できなければならない。
- **FR-012**: 編集モードでは、接続の追加、接続先変更、削除、およびラベルと意味の変更が
  できなければならない。
- **FR-013**: 編集モードでは、レーンの追加、名称変更、順序変更、削除、およびノード所属の
  変更ができなければならない。
- **FR-014**: 執筆者は自動配置を再実行でき、必要に応じて個別ノードの手動配置を保持できなければ
  ならない。
- **FR-015**: 編集モードは未保存状態を明示し、執筆者が保存または破棄を明示的に選択できなければ
  ならない。
- **FR-016**: 執筆者は保存前の編集操作を取り消し、取り消した操作をやり直せなければならない。
- **FR-017**: 保存前に定義全体が検証され、エラーがある場合は対象要素と修正理由を示して保存を
  拒否しなければならない。
- **FR-018**: 保存は対象となるMarkdownブロックまたは外部定義ファイルだけを更新し、それ以外の
  内容、改行、前後の文章を変更してはならない。
- **FR-019**: 保存された定義は、視覚エディターを使わなくても人が読んで変更できる構造を
  維持しなければならない。
- **FR-020**: 編集開始後に保存対象が外部変更された場合、システムは変更を上書きせず、再読込または
  手動解決を選べる競合状態を表示しなければならない。
- **FR-021**: 外部定義の読込と保存は許可されたドキュメント領域内に限定され、領域外、曖昧、
  または走査を意図するパスを拒否しなければならない。
- **FR-022**: ローカルで定義を保存したとき、執筆者は開発環境を再起動せずに更新された図を
  確認できなければならない。
- **FR-023**: 読者は図を拡大、縮小、移動し、図全体へ戻せなければならない。
- **FR-024**: 読者はノードのラベルと説明を検索し、一致したノードへ移動できなければならない。
- **FR-025**: 読者はノードを選択して、説明、属性、関連リンク、直接の接続関係を確認できなければ
  ならない。
- **FR-026**: 読者は選択したノードの上流、下流、または特定経路だけを強調表示できなければ
  ならない。
- **FR-027**: 執筆者は名前付き経路を追加、編集、並べ替え、削除でき、読者はその経路を段階的に
  再生できなければならない。
- **FR-028**: 読者は一時的な選択や編集状態を含まない図全体を、共有可能な画像として取得できなければ
  ならない。
- **FR-029**: ノードのラベル、説明、担当、状態、および関連する説明文は、サイト全体の検索対象に
  含まれなければならない。
- **FR-030**: 図は選択中のドキュメントテーマに追従し、背景、文字、ノード、接続に読み取れる
  コントラストを保たなければならない。
- **FR-031**: 小さい画面または対話機能を利用できない環境では、ノード、接続、順序、説明を失わない
  読み取り可能な代替表示を提供しなければならない。
- **FR-032**: キーボード利用者は、ノード選択、詳細表示、ノードと接続の追加・変更、取り消し、
  保存、破棄を完了できなければならない。
- **FR-033**: 無効または未完成の定義は黙って消されず、最後に有効だった図または元のテキストと、
  対象箇所を特定できるエラーを表示しなければならない。
- **FR-034**: 公開用の静的サイトはすべての閲覧・探索機能を提供する一方、編集、ローカルファイル
  操作、ローカル絶対パスの公開を行ってはならない。
- **FR-035**: 定義に任意の実行コードを含めたり、表示または編集を通じて任意の処理を実行したり
  できてはならない。

### Key Entities *(include if feature involves data)*

- **Flow Document**: 1つのワークフローを表す正本。形式バージョン、識別情報、メタデータ、
  レーン、ノード、接続、名前付き経路、保存場所を持つ。
- **Node**: ワークフロー内の処理、判断、サービス、外部システム、注記。安定したID、種類、
  ラベル、任意の詳細情報と配置を持つ。
- **Edge**: 2つのノード間の方向付き関係。始点、終点、任意のラベルと意味を持つ。
- **Lane**: ノードを担当者、システム、境界などでまとめる領域。複数のノードを含む。
- **Named Path**: 正常系、異常系、リトライなど、説明順を持つノードと接続の集合。
- **Source Reference**: Markdown内の定義または外部定義の保存場所と、競合検出に必要な読込時点の
  状態を表す。
- **View State**: 読者の拡大率、表示位置、選択、検索、強調状態。正本の内容とは分離され、明示的な
  編集保存がない限り定義へ書き込まれない。

### Scope Boundaries

**In scope for the initial release**:

- workflow形式の図、5種類以上の定義済みノード、レーン、方向付き接続。
- Markdown内と外部ファイルの両方を正本にできる表示・視覚編集・安全な往復保存。
- 自動配置と手動配置、検索、詳細、上流・下流フォーカス、名前付き経路、画像取得。
- ローカル執筆環境での編集と、公開静的サイトでの閲覧専用表示。
- 既存のMarkdown機能、全文検索、テーマ、静的ビルドとの共存。

**Out of scope for the initial release**:

- ワークフローを実際に実行、スケジュール、監視する機能。
- 複数ユーザーによる同時共同編集、コメント、承認ワークフロー。
- 自由描画、付箋、手書き、汎用ホワイトボード機能。
- architecture、sequence、data-flow、lifecycleなどworkflow以外の図種。
- リポジトリや実行環境を解析して図を自動生成・自動同期する機能。
- 公開静的サイトから元ファイルを編集する機能。

### Dependencies

- 既存のローカル執筆環境が、対象ドキュメントを安全に読み書きし、外部変更を検知できること。
- 既存のドキュメント生成処理が、Markdown本文と外部定義の変更をページ更新へ反映できること。
- 既存のサイト検索が、ページから抽出されたワークフローの文言を索引へ含められること。
- 既存のテーマと公開処理が、対話可能な図と読み取り用の代替表現を配信できること。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 初めて利用する執筆者が、4ノードの既存定義に対してノード移動、ノード追加、
  接続変更を行い、5分以内に保存と再読込確認を完了できる。
- **SC-002**: ユーザビリティテスト参加者の90%以上が、外部の説明を受けずに編集、取り消し、
  保存、破棄の各操作を正しく完了できる。
- **SC-003**: 100ノード、150接続までの有効な図の95%以上が、ページ表示開始から2秒以内に
  閲覧・編集可能になり、検索、選択、移動操作へ200ミリ秒以内に視覚的反応を返す。
- **SC-004**: 保存テストの100%で、対象ブロックまたは対象ファイルだけが変更され、保存後の
  再読込でノード、接続、レーン、配置、名前付き経路が欠落なく再現される。
- **SC-005**: 無効入力と編集競合のテストケースの100%で破壊的な上書きが防止され、利用者が
  問題の対象と次に取れる行動を確認できる。
- **SC-006**: 公開用テストページの100%で編集機能とローカル絶対パスが露出せず、図の情報は
  閲覧可能な形で保持される。
- **SC-007**: テスト対象の全ノードについて、ラベルまたは説明の固有語をサイト検索すると、
  そのノードを含むページへ到達できる。
- **SC-008**: キーボードのみの操作で、主要な閲覧操作とノード・接続編集、取り消し、保存、
  破棄の受け入れシナリオを100%完了できる。
- **SC-009**: 比較テスト参加者5人中4人以上が、同等のテキスト図を直接編集する場合よりも、
  視覚編集の方が変更内容を把握しやすく、作業しやすいと評価する。
- **SC-010**: 同じ有効な定義と表示設定を繰り返し読み込んだ比較テストの100%で、ノードと接続の
  意味、順序、グループ、および保存済み配置が一致する。

## Assumptions

- 初期リリースはworkflow形式に限定し、他の図種は同じ概念モデルを拡張できる将来候補とする。
- 視覚編集はデスクトップ相当のローカル執筆環境を主対象とし、小さい画面では閲覧用の代替表示を
  優先する。
- 編集内容は自動保存せず、明示的な保存・破棄と未保存表示を標準動作とする。
- 外部定義は許可されたドキュメント領域内に置かれ、複数ページから参照できる。
- 執筆者は信頼されたリポジトリ利用者だが、定義内容とパスは常に検証対象とする。
- ソースコードへのローカル参照は執筆環境だけで利用でき、公開サイトではドキュメント相対または
  公開可能なリンクだけを表示する。
- 本機能はワークフローを説明するものであり、図に記載された処理を実行しない。
- 既存のMarkdown表現、テーマ、検索、公開ビルドの利用者体験は維持される。
- 対象規模は1図あたり最大100ノード、150接続を初期品質基準とする。
